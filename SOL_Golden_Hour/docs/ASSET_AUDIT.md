The new build uses the existing static-site approach rather than migrating to a large framework.

Other existing routes return to the current corporate site in the preview. A production migration must retain those routes appropriately and remove external redirects that would point back to themselves.

The discovered legacy capture issue is not silently fixed in production. The new preview avoids that pattern entirely: local preparation has no receipt claim; the isolated server returns success only after a committed record. Approved live-control mappings remain a separate release gate.
